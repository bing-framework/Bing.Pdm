# Bing.Pdm 技术文档

本文档面向需要在 .NET 项目中集成或二次开发 Bing.Pdm 的开发者，覆盖项目概述、运行环境、安装步骤、目录结构、模块接口、调用方式、参数与返回值、常见问题，以及当前信息不足以确认的待补充项。

术语约定：首次出现的专业术语保留英文原文并附中文说明，例如 PDM（Physical Data Model，物理数据模型）、DBMS（Database Management System，数据库管理系统）、CLR（Common Language Runtime，公共语言运行时）、OOXML（Office Open XML，Office 开放 XML 文档格式）、RTF（Rich Text Format，富文本格式）。

## 1. 项目概述

### 1.1 项目简介

Bing.Pdm 是一个 .NET 类库，用于在**不安装 PowerDesigner（SAP 出品的建模工具）**的前提下读取其导出的 XML 格式 PDM 文件。解析器产出的单一模型对象可同时驱动多种下游产物：JSON 序列化、Markdown 与离线 HTML 数据字典、物理图（Physical Diagram，即表关系图）的 SVG 渲染，以及 C# 实体代码生成。

项目同时提供一个 `net8.0` 命令行工具 `Bing.Pdm.Tool`，将上述能力封装为 `export`、`generate`、`migrate` 与 `diff` 子命令。

### 1.2 核心功能

| 功能 | 说明 | 对应类型 |
| --- | --- | --- |
| PDM 解析 | 读取 XML PDM，产出统一模型；兼容多种 PDM 变体的集合命名 | `PdmReader`、`PowerDesignerParser` |
| JSON 导出 | 序列化完整模型，保留原始 PDM ID，无引用环 | `PdmExporter`（`PdmExportFormat.Json`） |
| Markdown 数据字典 | 表格化的库表结构说明，含键、索引、引用、视图与诊断 | `PdmExporter`（`PdmExportFormat.Markdown`） |
| 离线 HTML 数据字典 | 内嵌 CSS/JS/SVG 的单文件页面，支持搜索、目录、缩放与图元跳转 | `PdmExporter`（`PdmExportFormat.Html`） |
| SVG 物理图 | 每个物理图输出独立 SVG，保留矩形与连接线折点 | `SvgDiagramRenderer`、`PdmExporter.WriteDiagram` |
| Excel 导出 | 生成多工作表工作簿，纯 OOXML 实现，无需 Office | `PdmOfficeExporter.WriteExcel` |
| Word 导出 | 生成横向数据字典文档，表头跨页重复 | `PdmOfficeExporter.WriteWord` |
| C# 实体生成 | 每表生成一个实体文件，支持 DBMS 分域类型映射 | `EntityGenerator`、`CSharpTypeMapper` |
| 诊断收集 | 解析与生成过程中的问题以诊断码汇总，随各格式一并导出 | `PdmDiagnostic`、`CSharpGenerationDiagnostic` |

### 1.3 支持范围与已知限制

| 项目 | 状态 |
| --- | --- |
| 受支持的输入格式 | XML PDM 家族，以 `templates/pdm_template.xml` 与测试 fixture 为代表 |
| 已解析对象 | 模型元数据、包、表、列、键、索引、视图、引用与连接、表快捷方式、物理图图元 |
| 集合名兼容 | 同时接受 `Columns`/`ColumnInfos`、`Keys`/`KeyInfos`、`Indexes`/`IndexeInfos` |
| 安全限制 | 拒绝 XML DTD 与外部实体 |
| 复制元数据 | 解析 `TargetModel`、`Replication`、`SubReplication` 及会话引用，并保留元数据与诊断；不计入主模型业务对象集合 |
| 快捷方式解析范围 | 单模型解析保留本模型目标；通过 `PdmWorkspaceResolver` 可按清单解析跨模型 Shortcut、关系端点、列关联与图元 |
| 图形保真度 | 不还原 PowerDesigner 的字体、阴影、视觉效果及全部图元类型；仅保留矩形、连接路径与基本 BGR `COLORREF` 颜色 |
| 注释文本 | RTF 注释转为转义纯文本，支持 CP936 中文 |

## 3. 安装与快速上手

### 3.1 获取源码

```bash
git clone https://github.com/bing-framework/Bing.Pdm.git
cd Bing.Pdm
```

### 3.2 还原与构建

```bash
dotnet restore Bing.Pdm.sln
dotnet build Bing.Pdm.sln
```

构建应输出「0 个警告、0 个错误」。仓库约定构建必须保持零警告。

### 3.3 运行测试

```bash
dotnet test Bing.Pdm.sln
```

测试使用 `tests/Bing.Pdm.Tests/Fixtures` 下的 PDM 样例文件，这些文件通过项目中的 `PreserveNewest` 项复制到输出目录。

### 3.4 浏览器冒烟测试（可选）

该测试在真实浏览器中打开导出的 HTML，校验搜索、图表链接与缩放、外部请求、浏览器错误及窄视口表现。

```bash
cd tests/browser-smoke
npm ci
npx playwright install chromium
npm test
```

若希望复用已安装的 Chromium 内核浏览器（如 Edge），设置环境变量 `PDM_BROWSER_EXECUTABLE` 指向其可执行文件路径。该测试通过 `dotnet run --no-restore` 调用 CLI，因此首次运行前必须先完成 `dotnet restore`。

### 3.5 快速上手

以下示例基于仓库自带 fixture `tests/Bing.Pdm.Tests/Fixtures/complete.pdm`（SQL Server 模型，含两个表、一个视图、一个引用及一处故意构造的失效父表引用）。

**导出全部格式的数据字典：**

```bash
dotnet run --project samples/Bing.Pdm.Tool -- export tests/Bing.Pdm.Tests/Fixtures/complete.pdm out json,md,html,xlsx,docx zh
```

标准输出为产生的文件路径，标准错误为诊断信息：

```

out/complete.md
out/complete.html
out/complete.xlsx
out/complete.docx
```

```

```

**生成 C# 实体：**

```bash
dotnet run --project samples/Bing.Pdm.Tool -- generate tests/Bing.Pdm.Tests/Fixtures/complete.pdm gen Demo.Entities
```

产出 `gen/Order.cs` 与 `gen/Customer.cs`：

### 5.2 读取层

#### `IPdmReader`

命名空间 `Bing.Pdm`。定义 PDM 文件的读取契约。

| 方法 | 签名 | 返回值 | 异常 |
| --- | --- | --- | --- |
| `ReadFromFile` | `PdmInfo ReadFromFile(string filePath)` | 解析后的模型 | `ArgumentException`：`filePath` 为空或仅空白；`IOException`：读取发生 I/O 错误 |
| `Read` | `PdmInfo Read(Stream stream)` | 解析后的模型 | `ArgumentNullException`：`stream` 为 `null`；`InvalidDataException`：文档中不含模型节点；`XmlException`：输入非格式良好的 XML |

`Read` 从流的**当前位置**开始读取，且**不会关闭**传入的流，调用方负责释放。

#### `PdmReader`

命名空间 `Bing.Pdm.Reader`，`sealed` 类，实现 `IPdmReader`，为默认实现。`ReadFromFile` 内部以 `File.OpenRead` 打开并释放文件流，`Read` 委托给 `PowerDesignerParser.Parse`。

```csharp
using Bing.Pdm;
using Bing.Pdm.Reader;

var model = new PdmReader().ReadFromFile("model.pdm");
```

### 5.4 导出层：`PdmExporter`

命名空间 `Bing.Pdm`，`sealed` 类，实现 `IPdmExporter` 与 `IPdmExportLabelProvider`。

#### 枚举

`PdmExportFormat`：`Json`、`Markdown`、`Html`、`Svg`。

`PdmExportLanguage`：`English`、`Chinese`。

#### 构造函数

| 重载 | 说明 |
| --- | --- |
| `PdmExporter()` | 英文标签，无自定义标签与模板 |
| `PdmExporter(PdmExportLanguage language)` | 指定语言 |
| `PdmExporter(PdmExportLanguage language, IPdmExportLabelProvider labelProvider)` | 指定语言与标签提供器 |
| `PdmExporter(PdmExportLanguage language, IPdmExportLabelProvider labelProvider, IEnumerable<IPdmExportTemplate> templates)` | 另注册自定义模板 |

构造函数在以下情况抛出 `ArgumentException`：`templates` 含 `null` 项、存在重复格式、或模板格式不是 `Markdown`/`Html`（自定义模板仅支持这两种格式）。

#### 方法

| 方法 | 签名 | 返回值 | 异常 |
| --- | --- | --- | --- |
| `Write` | `void Write(PdmInfo model, PdmExportFormat format, TextWriter writer)` | 无 | `ArgumentNullException`：`model` 或 `writer` 为 `null`；`InvalidOperationException`：导出 `Svg` 时模型不是**恰好**含一个物理图；`ArgumentOutOfRangeException`：格式不受支持 |
| `WriteDiagram` | `void WriteDiagram(PdmInfo model, PhysicalDiagramInfo diagram, TextWriter writer)` | 无 | `ArgumentNullException`：任一参数为 `null` |
| `GetLabel` | `string GetLabel(string key)` | 按当前语言解析的标签文本 | `ArgumentNullException`：`key` 为 `null` |

导出 `Svg` 时若模型含多个物理图，应改为遍历 `AllPhysicalDiagrams` 逐个调用 `WriteDiagram`。

```csharp
using Bing.Pdm;
using Bing.Pdm.Reader;

var model = new PdmReader().ReadFromFile("model.pdm");
var exporter = new PdmExporter(PdmExportLanguage.Chinese);

using (var md = File.CreateText("dictionary.md"))
    exporter.Write(model, PdmExportFormat.Markdown, md);

foreach (var diagram in model.AllPhysicalDiagrams)
{
    using var svg = File.CreateText($"{diagram.Code ?? diagram.Id}.svg");
    exporter.WriteDiagram(model, diagram, svg);
}
```

### 5.5 Office 导出：`PdmOfficeExporter`

命名空间 `Bing.Pdm`，`sealed` 类，实现 `IPdmOfficeExporter`。直接生成 OOXML 包（ZIP + XML），不依赖 Office 客户端或第三方文档库。

#### 构造函数

| 重载 | 说明 |
| --- | --- |

#### `EntityGenerator`

| 方法 | 签名 | 返回值 |

参数说明：

| 参数 | 说明 |
| --- | --- |

| `output` | 实体文件输出目录 |

#### `CSharpTypeMapper`

`sealed` 类，负责数据库类型到 CLR 类型的映射。

| 方法 | 签名 | 返回值 | 异常 |
| --- | --- | --- | --- |
| `RegisterFallback` | `void RegisterFallback(string clrType, bool referenceType = true)` | 无 | `ArgumentException`：`clrType` 不是合法 C# 类型名 |
| `RegisterMapping` | `void RegisterMapping(string databaseType, string clrType, string? dbms = null, bool referenceType = true)` | 无 | `ArgumentException`：类型名不合法 |
| `Resolve` | `CSharpTypeResolution Resolve(ColumnInfo column, string? dbmsCode, string? dbmsName)` | `CSharpTypeResolution` | 解析失败时不抛出，改为返回结果对象 |
| `GetCSharpType` | `string GetCSharpType(ColumnInfo column, string? dbmsCode, string? dbmsName)` | 含可空性处理的 C# 类型名 | `ArgumentNullException`；`InvalidOperationException`：类型不受支持 |

参数说明：

| 参数 | 说明 |
| --- | --- |
| `databaseType` | 数据库类型名，比较前会转小写并折叠空白，且先按完整类型再按去长度参数的基础类型匹配 |
| `clrType` | 目标 CLR 类型名，须匹配 `^(?:global::)?[_\p{L}][\p{L}\p{Nd}_]*(?:\.[_\p{L}\p{Nd}_]*)*(?:\[\])?$` |
| `dbms` | DBMS 名称或代码；为 `null` 或空时注册适用于所有厂商的全局映射 |
| `referenceType` | 为 `true` 时，可选列直接使用引用类型而不追加 `?` 后缀 |

**映射优先级**（依源码实际执行顺序）：

1. 自定义映射 —— 当前 DBMS 的完整类型名
2. 自定义映射 —— 当前 DBMS 的基础类型名
3. 自定义映射 —— 全局（`*`）完整类型名
4. 自定义映射 —— 全局（`*`）基础类型名
5. DBMS 内置特例规则
6. 通用类型映射表
7. 兜底映射（仅当通过 `RegisterFallback` 注册）

> 注意：`README.md` 中描述的优先级为「DBMS 精确/基础 → DBMS 内置 → 全局精确/基础 → 兜底」，与源码实际顺序（全局自定义映射先于 DBMS 内置规则）不一致。本文档以源码为准，README 相关表述待修正。

**DBMS 归一化**：`dbmsCode` 与 `dbmsName` 拼接后转小写，按子串匹配归一化为 `sqlserver`（含 `mssql`、`sql server`）、`postgresql`（含 `postgres`、`pgsql`）、`mysql`（含 `mariadb`）、`oracle`。

**可空性规则**：列非必填（`Mandatory` 为 `false`）且映射非引用类型时，在类型名后追加 `?`。

**通用类型映射表**（`MapCommonType`）：

| 数据库类型 | CLR 类型 |
| --- | --- |
| `int`、`integer`、`serial`、`mediumint` | `int` |
| `bigint`、`bigserial` | `long` |
| `smallint` | `short` |
| `tinyint` | `byte` |
| `year` | `short` |
| `bit`、`bool`、`boolean` | `bool` |
| `decimal`、`numeric`、`money`、`number` | `decimal` |
| `float` | `double` |
| `real`、`binary_float` | `float` |
| `binary_double` | `double` |
| `date`、`datetime`、`datetime2`、`timestamp` | `DateTime` |
| `datetimeoffset`、`timestamptz` | `DateTimeOffset` |
| `time` | `TimeSpan` |
| `uniqueidentifier`、`uuid` | `Guid` |
| `binary`、`varbinary`、`image`、`rowversion`、`bytea`、`raw`、`blob`、`mediumblob`、`longblob`、`bfile` | `byte[]` |
| `char`、`character`、`nchar`、`varchar`、`character varying`、`nvarchar`、`varchar2`、`nvarchar2`、`text`、`ntext`、`longtext`、`mediumtext`、`clob`、`nclob`、`json`、`jsonb`、`xml`、`enum`、`set` | `string` |
| `sql_variant` | `object` |

**DBMS 内置特例**：

| 条件 | 结果 |
| --- | --- |
| MySQL 且类型以 `tinyint(1)` 开头 | `bool` |
| MySQL 整数及 `unsigned` 变体 | `tinyint`→`sbyte`/`byte`，`smallint`→`short`/`ushort`，`mediumint`/`int`/`integer`→`int`/`uint`，`bigint`→`long`/`ulong` |
| SQL Server 且基础类型为 `timestamp` 或 `rowversion` | `byte[]` |
| PostgreSQL `timestamp` | 含 `with time zone` 或 `timestamptz` → `DateTimeOffset`，否则 `DateTime` |
| PostgreSQL `time` | `timetz` 或 `time with time zone` → `DateTimeOffset`；`time` / `time without time zone` → `TimeSpan` |
| Oracle `timestamp` | 含 `with time zone` 或 `with local time zone` → `DateTimeOffset`，否则 `DateTime` |
| PostgreSQL（附加） | `int2`/`smallserial`/`serial2`→`short`，`int4`/`serial`/`serial4`→`int`，`int8`/`bigserial`/`serial8`→`long`，`double precision`→`double`，`interval`→`TimeSpan` |
| Oracle（附加） | `pls_integer`/`binary_integer`→`int`，`rowid`/`urowid`→`string` |

```csharp
var mapper = new CSharpTypeMapper();
mapper.RegisterMapping("geography", "My.App.Geography", "MSSQLSRV");
mapper.RegisterFallback("object");

var resolution = mapper.Resolve(column, model.DbmsCode, model.DbmsName);

```

## 6. 命令行接口

`samples/Bing.Pdm.Tool` 提供 CLI，参数不足或子命令错误时打印用法并返回退出码 2。

```
pdm export <input.pdm> <output-dir> [json,md,html,svg,xlsx,docx] [en|zh]
pdm generate <input.pdm> <output-dir> [namespace] [--map <dbms|*>:<database-type>=<C#-type>]... [--fallback-type <C#-type>]
```

### 6.1 `export`

| 位置 | 参数 | 必填 | 说明 |
| --- | --- | --- | --- |
| 1 | `input.pdm` | 是 | 输入 PDM 文件路径 |
| 2 | `output-dir` | 是 | 输出目录，不存在时自动创建 |
| 3 | 格式列表 | 否 | 逗号分隔，缺省为 `json,md,html` |
| 4 | 语言 | 否 | `en`/`en-us`/`english` 或 `zh`/`zh-cn`/`chinese`，缺省 `en` |

格式名称映射：

| CLI 名称 | 产物 | 实现 |
| --- | --- | --- |
| `json` | `<basename>.json` | `PdmExportFormat.Json` |
| `md`、`markdown` | `<basename>.md` | `PdmExportFormat.Markdown` |
| `html` | `<basename>.html` | `PdmExportFormat.Html` |
| `svg` | `<basename>-<diagram>.svg`，每个物理图一个文件 | `WriteDiagram` |
| `xlsx`、`excel` | `<basename>.xlsx` | `PdmOfficeExporter.WriteExcel` |
| `docx`、`word` | `<basename>.docx` | `PdmOfficeExporter.WriteWord` |

模型不含物理图时，`svg` 导出失败并提示 `The model has no physical diagrams to export.`。格式名大小写不敏感，重复的格式只处理一次。

### 6.2 `generate`

| 位置 | 参数 | 必填 | 说明 |
| --- | --- | --- | --- |
| 1 | `input.pdm` | 是 | 输入 PDM 文件路径 |
| 2 | `output-dir` | 是 | 实体输出目录 |
| 3 | `namespace` | 否 | 目标命名空间，缺省 `Generated.Entities`；以 `--` 开头时视为选项 |
| — | `--map` | 否 | 可重复，格式 `<dbms|*>:<database-type>=<C#-type>` |
| — | `--fallback-type` | 否 | 无法解析类型时使用的兜底 C# 类型 |

`--map` 中 `*` 表示全局映射，否则按 DBMS 代码或名称匹配。

**行为对照**（实测，输入为含 `geography` 列的模型）：

| 场景 | 输出 | 退出码 |
| --- | --- | --- |
| 不指定兜底 | `TYPE_ERROR [Customer.Name]: Unsupported database type 'geography' for DBMS 'Microsoft SQL Server' at column 'Name'.`，不创建输出目录 | 1 |
| 指定 `--fallback-type object` | `TYPE_FALLBACK [Customer.Name]: ...`，写入文件，列类型替换为 `object` | 0 |
| 指定 `--map MSSQLSRV:geography=My.App.Geography` | 正常写入，列类型为 `My.App.Geography` | 0 |

### 6.3 退出码

| 退出码 | 含义 |
| --- | --- |
| 0 | 成功（可能伴随 `UNRESOLVED_REF` 等非致命诊断，输出到标准错误） |
| 1 | 失败：I/O 错误、XML 格式错误、参数错误、无效操作，或生成阶段存在 `TYPE_ERROR` |
| 2 | 命令行参数不足或子命令不是 `export`/`generate` |

## 8. 常见问题与注意事项

### 8.1 诊断相关问题

**Q：导出的文件能直接使用吗？**

应先检查 `PdmInfo.Diagnostics`。诊断会写入全部导出格式，存在 `UNRESOLVED_REF`、`MISSING_REF` 等条目说明模型中有引用未能解析，据此生成的 schema 可能不完整。

**Q：为什么生成实体时提示 `TYPE_ERROR` 且没有产出任何文件？**

默认策略是严格的：先扫描所有列完成类型解析，任一列无法解析即汇总报错、返回退出码 1 且不创建输出目录。这是有意为之，避免产出类型错误的半成品代码。若希望先产出再逐一修正，使用 `--fallback-type object`（编程方式对应 `CSharpTypeMapper.RegisterFallback`），此时会改为 `TYPE_FALLBACK` 警告并继续生成。

**Q：`TYPE_FALLBACK` 会不会掩盖拼写错误的类型名？**

不会。映射器不会猜测拼错的 SQL 类型，兜底仅替换确实无法识别的类型，并逐列打印警告。

### 8.2 使用方式相关问题

**Q：JSON 里为什么找不到 `AllTables`？**

`AllTables`、`AllViews`、`AllReferences`、`AllShortcuts`、`AllPhysicalDiagrams` 是 `PdmInfo` 上的运行时计算属性，不参与序列化。JSON 中只有根级集合与递归的 `Packages`；需要扁平化时请在代码中访问这些属性。

**Q：模型有多个物理图时导出 SVG 报错？**

`PdmExporter.Write` 传入 `PdmExportFormat.Svg` 要求模型**恰好**含一个物理图，否则抛 `InvalidOperationException`。多图场景应遍历 `AllPhysicalDiagrams` 逐个调用 `WriteDiagram`——CLI 的 `svg` 格式正是这样实现的。

**Q：`Read(Stream)` 会关闭我传入的流吗？**

不会。读取从流的当前位置开始，读完后流仍由调用方负责释放。`WriteExcel` 与 `WriteWord` 同样不会关闭传入的流。

**Q：可以脱离 PowerDesigner 和 Office 使用吗？**

可以。解析不依赖 PowerDesigner；Excel 与 Word 直接生成 OOXML 包，不需要 Office 客户端或外部服务。

### 8.3 兼容性问题

**Q：支持哪些 PDM 文件？**

支持的格式是以 `templates/pdm_template.xml` 和测试 fixture 为代表的 XML PDM 家族。解析器兼容 PDM 变体中的集合命名差异（`Columns`/`ColumnInfos`、`Keys`/`KeyInfos`、`Indexes`/`IndexeInfos`）。

**Q：哪些内容明确不受支持？**

复制元数据进入独立集合与 `MetadataLookup`，不增加业务对象数量，也不执行同步或属性继承。
跨模型 Shortcut 只访问显式工作区清单内的模型；不会按 URL 自动打开文件或网络资源。
PowerDesigner 模式读取基础字体、阴影、线型、RTF 段落及触发器清单，但未通过人工像素级验收。
自定义列过滤通过显式 `ColumnFilter` 处理；无法解释的表达式产生诊断。

**Q：中文注释能正确解析吗？**

RTF 注释会转为转义纯文本，包含 CP936 中文（依赖 `System.Text.Encoding.CodePages`）。

### 8.4 开发注意事项

- **核心库框架不可升级**：`src/Bing.Pdm` 必须保持 `netstandard2.0` 与 `LangVersion` 7.1，不得使用更高版本的语言特性或超出该框架的 API。
- **构建须零警告**：仓库约定 `dotnet build Bing.Pdm.sln` 输出 0 警告 0 错误。
- **公开成员需 XML 文档注释**：现有代码对公共类型与成员均有中文 XML 注释，新增代码应保持一致。
- **快捷方式保留原始引用**：快捷方式同时保留原始 PDM ID、ObjectID、TargetID 与解析后的目标 ID；关系与表图元另以独立字段保留原始 Shortcut 引用，与归一化后的真实表 ID 分开。
- **SmartCode 适配器仅供参考**：`samples/Bing.PdmGenerateDemo` 不在解决方案内，其依赖图仍含旧版包（含 NuGet 报告存在漏洞的包）。生产用途请使用 `Bing.Pdm.Tool` 这条 .NET 8 路径。

## 10. 本轮新增校验与消费契约

- `PdmModelValidator.Validate` 独立检查当前集合的身份与引用，返回问题而不改变 Lookup 或模型诊断。
- 结构差异报告的 `ValidationIssues` 只纳入结构问题；`--fail-on-incomplete` 返回 1，默认保留报告并返回 0。
- diff 的 `--before-workspace` / `--after-workspace` 按稳定模型 GUID 比较依赖，清单别名可不同。
- `MeasureText` 返回 PDM 坐标单位中的宽度；Windows CLI 使用 GDI，其余调用方未提供度量时产生估算诊断。
- CLI 先暂存再发布输出；进程内失败回滚，回滚失败保留恢复路径。该机制不保证进程强制终止或并发写入的原子性。
- JSON schema 仍为版本 1，新增可选字段包含表的 `Triggers` 与富文本段落对齐信息。
